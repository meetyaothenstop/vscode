# 主工程反向完整采用正向控制

用户明确要求先上传当前版本，再将反向控制环路全部换为正向控制，并要求备份能区分修改。
基线`pre-reverse-forward-control-20261110`→d000bfb已在任何控制源码编辑前推送并核对。
备份语义及旧固件指纹见`docs/版本与备份对照.md`。

## 目标与范围

MAIN mode3/mode4共用正向的初始化、PI、前馈、滤波、限幅、抗积分饱和、预充、锁存、
软启动和接管计算。电压PI0.3/8、电流PI0.015/20、Boost前馈倍率0.2、90%Vin预充；
取消MAIN反向独有的输出阈值HOLD/重新软启动调节，采用正向连续闭环。
保留独立方向控制状态，物理右输入/左输出、负IL与mode3→1/mode4→2映射。
反向ADC1物理通道保持；本次不改采样触发或校准。PWM比较值应严格是正向的左右镜像。

MAIN Buck50/10kHz、Boost25/5kHz、PWM/ADC/快速软件保护150kHz保持。
mode4欠压7V、其他三模式9V、42V输入上限、1A/3V启动互锁、OVP、绝对过流/方向/ADC/
硬件故障门控和时序截止保持；输出阈值HOLD是运行控制策略，独立OVP继续关断锁存。
默认正向18→3V、反向12→18V保持；既有主/bench工程，不操作板子。

## 实现选择

抽取现有forward.c为可独立实例化的私有`forward_controller_impl.inc`，配合原
`forward_step_impl.inc`。正向实例保持原符号和行为；MAIN反向建立私有I/O实例及独立B/X，
用轻量适配层换端口/电流符号并映射旧reverse_Y接口。
MAIN reverse_B/X类型与forward一致，调试字段变化必须记录。
非MAIN历史reverse实现单独保留，用于旧通用参考回归及受限bench，不能据它判断MAIN的新算法。

只改反向几个增益仍会遗留前馈/预充/HOLD差异；复制完整正向算法会再次漂移，均不采用。
这种共用代码、保留独立状态的方案由助手选择，符合用户“全部跟正向一样”的明确要求。

## 验收

以备份标签的独立正向旧源作为参考，逐位对比MAIN反向在镜像输入后的全部B/X/输出，
覆盖150kHz兼容、50/10kHz Buck、25/5kHz Boost、随机反馈/饱和/重初始化/非法输入和方向切换。
正反状态不能相互覆盖。MAIN实际后端在目标附近/合成尖峰中不再进入旧HOLD；独立OVP等仍生效。
完整主机回归、四模式名义开关模型、主/bench ARM6.18构建、实际HEX/AXF/CCM/快速整数路径、
独立审查通过，再提交、打新标签、上传核对。bench HEX保持，正向算法和实际输出不能退化。
验收包括真实保护后端的预期关断：共用正向算法不等于扩大其原有启动包络。已确认的24/35→36V
模型启动过流须保留7.5A保护并明确记录，不能抬门限或当成稳压成功。
不宣称实板16V根因已确定、振荡已解决、最坏时序或硬件OCP已验证。
