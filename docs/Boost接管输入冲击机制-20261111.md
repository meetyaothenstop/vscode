# Boost接管时输出低于输入：主机机制补充（2026-11-11）

本轮回答“为什么轻载时预充转Boost仍可能拉低输入”。只分析控制源码并运行主机模型，
没有修改固件或操作板子。FCTRL1控制源码为69f9cd5；用户当前默认反向18→36V改动保留且未提交。
本试验显式请求右侧12→18V/100Ω，与菜单默认值无关。

## 代码中可确认的条件

- 预充完成判据为数字滤波后的输出电压超过0.90×实测输入；12V输入门限约10.8V。
- Boost PWM映射将输入桥高侧有效占空比固定约0.85，输出桥约0.85×(1−D)，命令D最低0。
- 因此在输出仍低于输入时，即使D=0，理想平均电感电压仍约为0.85×(Vin−Vout)，
  还需扣除电阻压降。电流不能靠继续减小Boost命令来快速压住，因为命令已到下限。
- 控制器按25kHz更新，即40us一步；已有的换向全关断和PI接管斜坡不等于按电源0.9A限制输入电流。

这表示当前策略有一段从约90%Vin充到Vin附近的Boost接管冲击风险。实际是否形成输入欠压，
仍取决于电源动态限流、输入电容/阻抗及实际开关行为。轻负载降低的是电阻负载的稳态功率需求，
输出电容从低电压继续充电的需求仍存在。

## 本轮新增加的模型相位证据

使用现有真实快/慢后端、理想12V输入、22uH/460uF/100Ω名义开关模型；时间为模型启动计时：

|时刻|状态与数据|
|---|---|
|23.5800ms|RUNNING→CHANGEOVER，物理输出10.91305V，物理IL−0.31946A，BOOST_RUN=0|
|23.6267ms|CHANGEOVER→RUNNING，开始Boost，物理输出10.90221V、IL约0，参考14.81292V|
|23.7800ms|PWM周期平均输入电流峰值3.855834A，物理输出11.78070V，占空命令已降为0|
|结束|输出17.994V、参考18V、duty约0.3335，稳态物理IL采样约−0.2387A|

峰值出现在重新开通后约0.1533ms，且此时输出仍低于输入、Boost命令已到0，
支持上述模型中的最低占空比控制限制。换向关断阶段电流已归零，不能把本试验峰值解释为
“全关断没有清掉原来的电感电流”。

这些数值是合成模型，输入源本身保持理想12V，没有模拟用户电源0.9A限流，
所以它证明接管有瞬时电流需求，**不证明实板实际峰值或原8.99V故障根因**。
临时源/可执行文件为Git忽略目录`.superpowers/reverse-forward-control/handover_cause_probe.*`。

## 后续判断边界

若实板源供电不足以承担该瞬态，差额由板端输入电容提供，输入电压可能降低并触发欠压；
也仍需排除ADC开关干扰。应对应切换时刻观测板端Vin，而不能仅用电源面板平均值作结论。
改进需要受控的Buck/Boost过渡；不能直接把预充门限设为100%就称问题解决，
现有Buck占空比上限与自举刷新会影响它能否达到该门限。
