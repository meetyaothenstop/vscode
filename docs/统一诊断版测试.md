# 12V统一诊断版：同一次故障的阶段、采样与耗时

本版用于定位T3和S8/S9，尚未宣称修复实板启动。OLED发送仍为原轮询接口；
沿用OLED-MUTE策略，启动准备/运行时暂停绘图和I2C刷新，故障/停机恢复。
未改变PI、CPU/PWM频率、ADC触发、启动顺序、保护门限或硬件保护就绪状态。

## 唯一的本轮交付

- 工程：`MDK-ARM/bench12_unified_diag.uvprojx`
- Target：`bench12_unified_diag`
- HEX：`MDK-ARM/bench12_unified_diag/bidreaction_bench12_unified_diag.hex`
- AXF：同目录下同名`.axf`
- 首页：**12V UNIFIED DIAG**；参数页：**SW-DIAG**。
- 宏：`POWER_BENCH_12V_BUCK_TEST=1`、`POWER_TEST_SKIP_OLED_ACTIVE=1`、
  `POWER_UNIFIED_DIAGNOSTICS=1`、`POWER_OCP_WIRING_CONFIRMED=0`。

仅正向Buck、输入实测10.5～13.5V、目标1～6V；电流给定上限0.5A、采样
过流1.5A。启动近零检查仍为|IL|<0.25A及输出≤0.25V，时序门限仍为840/936
周期。这些是软件采样条件，不是瞬时峰值或硬件安全能力的保证。

## 一次复现怎样保存

旧现场先保存截图，下载/清故障会丢失旧快照。助手只构建文件，不下载或启机。
用户手动下载本版后确认工程、Target和首页标识。保留12V、限流0.2A、100Ω
负载和6V目标；启动前确认实际右输出已低于0.25V，并满足原测试准备条件。

1. CPU正常运行时按start一次。若无明确故障而屏幕冻结，先按K4停机；
   画面冻结不代表功率级停机。运行中不要断点、暂停或单步控制中断。
2. 确认故障停机后再在Keil暂停。在预填Watch1展开`power_diag.fault`，以及
   `power_diag.fault.profile`和其中`checkpoint_cycles`，保存所需的多张截图。
   这是同一个锁存对象，不需要再逐项手工录入表达式。先记录，后清故障。
3. 同时注明本次OLED故障码、负载接法、示波器测点/触发设置和是否触发。
   不把不同次启动的S9快照与T3波形混用。

## 首故障字段

`power_diag.irq`是仍会变化的实时探针；**只用`power_diag.fault`归因**。
成功显式清故障会清空fault并回STOPPED，不自动启动；硬件来源仍有效时清除
失败，原记录保留。后续ADC刷新、其他故障或新的拒绝请求不会覆盖首故障。

| 字段（均在power_diag.fault中） | 含义 |
| --- | --- |
| fault / detail | 首故障位与子码；power_status.fault可能随后累计其他故障位 |
| state | 置为FAULT之前的状态：0停止、1自举、2arming、3运行、5换向、6保持 |
| context | 1初始化、2前台启动请求、3控制中断、4硬件故障中断、5其他前台 |
| start_pending | 1且state=0：请求接受后的新采样检查，尚未调用首次自举使能 |
| bootstrap_remaining / arming_remaining | 对应状态的剩余计数；其他状态为0 |
| bootstrap_resume | 1是HOLD恢复；不能按冷启动残压条件解释 |
| mode / target_volts | 控制模式与目标；前台拒绝时为本次请求参数 |
| samples | 首故障时最后一组完整样本编号 |
| sample_fresh | 1：本次控制IRQ已读完并换算ADC；0：前一完整样本或前台快照 |
| raw_vh / raw_vl / raw_il | 同次锁存的ADC原始码 |
| v_left / v_right / il | 与上述原始码对应的物理量；并非独立实测证明 |
| timing_elapsed_cycles / timing_spacing_cycles / timing_counter_ticks | 精确的T子码触发测量；其他首故障均为0 |
| capture_elapsed_cycles | 控制IRQ入口至输出禁用后的诊断采集点；含关断开销，不能代替T3测量 |

S8/S9时同时看state、start_pending和profile.entry_state：区分首次自举前、自举
中和arming中。T3若entry_state=2而state=3，说明发生在arming转运行的那一轮。
不能把state=3理解为已持续运行，也不能仅凭无输出触发推断没有门极脉冲。

T1/T2在读取本轮ADC之前判断，因此sample_fresh=0；ADC缺失故障也是0。
快照此时是上一完整样本，不能冒充触发时刻的新模拟量。

## 分段耗时

`profile.stage`：0不在控制IRQ；1入口/硬件与入口时序检查；2ADC；3保护；
4启动/状态转换；5控制器；6PWM映射；7写寄存器前时限；8写寄存器/恢复；9尾部。

`profile.entry_state`为本轮IRQ开始时状态。entry_samples是入口样本编号；
entry_spacing_cycles、entry_counter_ticks是入口间隔和计数器；入口硬件检查
就故障时，这两项尚未取得，保持0。

checkpoint_cycles按下表存储**从同一IRQ入口起算的累计CPU周期**，不是直接
的分段周期。150MHz下除以150得到微秒。用相邻已完成点相减得到区域耗时。

| 下标 | 完成点 | 对应valid_mask位 |
| --- | --- | --- |
| 0 | 入口检查完成 | 1 |
| 1 | ADC读取和换算完成 | 2 |
| 2 | 常规保护/冷启动检查完成 | 4 |
| 3 | 状态准备完成、进入控制器前 | 8 |
| 4 | 控制器计算完成 | 16 |
| 5 | PWM映射和状态遥测完成 | 32 |
| 6 | 写比较值或保持处理完成 | 64 |

**只有valid_mask置位的完成点有效。** 未走到的点在首故障中写0；0可能也代表
合法零周期主机模拟值，不能脱离mask解释。S8/S9通常mask=3，T3通常mask=63；
T3没有完成点6，不能据0推断寄存器写入耗时为0。

插桩读取DWT、保存时间戳和阶段会增加真实耗时，并计入原时序保护。区域差值
也包含边界探针开销，不是纯函数基准。本版未测得或减去一个假定开销；不能将
诊断版较慢直接归因于原控制器，也不能因为诊断版T3就扩大门限。用于找热点后，
需要用未插桩版本和实板波形验证优化收益与最终周期预算。

## 接下来如何使用证据

- T3：先看入口状态、阶段和0～5完成点，找出最长区域，再针对代码或执行存储器
  定位；与未插桩对照，不能直接宣称OLED/DMA是根因。
- S9：同次启动同时测实际右输出和PA1采样点；初标增益0.04666，0.589V输出
  换算对应PA1约27.5mV。故障样本可能来自采样前端/ADC偏差，也可能有真实暂态。
- S8：先核验INA240供电、零点、已知电流增益、方向和电阻实际位置，再评估
  对应启动阶段的近零门限。当前不把它替换为6A运行限流。

主机测试只证明记录和状态机行为，Keil编译只证明可构建；实际插桩耗时、
闭环、门极/死区、采样瞬态及保护时延仍需实板验证。
