# 故障报错对照清单

整理日期：2026-11-09。依据《双向buckboost.md》历史记录及当前故障代码；本日后续已按用户要求将反向Boost门限和控制频率对齐正向Boost，未操作板子。

**“触发条件”是代码已经确认的判断；“物理原因”可能仍需测量。不要把保护被触发，直接等同于硬件已经损坏或采样一定误报。** 下表包含实际反馈；后面的完整S/T表供查阅，不表示每个子码都已在板上出现。

## 一、先看当前门限，避免混用历史版本

|项目|MAIN正向Buck、正向Boost、反向Buck|MAIN反向Boost|
|---|---|---|
|输入电压保护|9～42V|7～42V（用户要求试验）|

Buck还要求目标≤实际输入×0.95；Boost目标必须高于实际输入。以上启动1A、运行参考6A、采样过流7.5A和台式电源CC限流0.7/0.9A是不同概念。
受限bench使用独立策略：当前24V FAST配置输入20～28V、采样过流6A，电流参考仍1A；12V FAST配置输入10～14V、采样过流1.5A。不能套用MAIN门限。

## 二、你实际提过的报错与排查结论

|**2 IN10.31V**（旧台架）|输入低于当时10.5V下限。|10.31V越过旧下限，独立于上一行的另一尝试；不能拼成同一波形。|

## 三、128 S1～S9完整对照

128表示启动拒绝或启动阶段复查不通过，S编号说明具体原因。该表是完整代码参考，不表示你实际遇到过全部九项。

|子码|触发条件|核对重点|
|---|---|---|
|S1|模式编号非法，或受限bench不支持所选模式。|MAIN mode1/2/3/4分别为正向Buck/Boost、反向Buck/Boost。|
|S2|样本不足两组或所需采样无效。|新鲜样本及ADC标志；不是“输入电压等于2V”。|
|S3|目标不在允许区间，包括NaN/无穷等非法目标。|MAIN Boost目标须在1～36V；Buck的0V是特定关断命令。|
|S4|启动请求时实际输入超出输入保护窗口。|MAIN反向Boost7～42V试验，其他三模式9～42V；检查ADC而不只看菜单设定。|
|S5|启动请求入口电流绝对值不满足启动互锁。|MAIN共享<1A；与S8判断时机不同。|
|S6|启动请求入口输出残压过高。|MAIN共享≤3V；与S9判断时机不同。|
|S7|启动模式/目标相对实际输入不合理。|Boost目标必须高于输入；MAIN Buck目标≤输入×0.95。|
|S8|请求接受后，待启动/自举/装载期间新采样电流超启动互锁。|看当次fault_il，不能用电源面板CC设置代替电感电流采样。|
|S9|同阶段电流检查通过，但输出残压超限。|看当次fault_v_left/right；停机后实时电压可能已经变化。|

重要区别：S5/S6是请求入口，S8/S9是接受请求后的新采样复查。仅在菜单输入框改电压，不会强行改变实际ADC测值。

## 四、64 T1～T7完整对照

时序值按当前150MHz CPU、150kHz PWM说明；旧截图应对照其所属版本。T1/T2/T6在历史文档中也有定义，以下完整列出，不据此认定各项都有可靠实板首包。

|子码|触发条件|直观解释|
|---|---|---|
|T1|相邻快速IRQ入口间隔>1256个CPU周期，约8.37μs。|中断入口间隔过长，可能被阻塞或延迟；并非只看本次函数耗时。|
|T2|快速IRQ入口HRTIM计数>8192ticks，约PWM周期起点后1.71μs。|这次进中断时，在PWM周期中的位置已经太晚。|
|T3|写前IRQ相对耗时>840个CPU周期，约5.60μs。|本次快速处理到写寄存器之前花费过久。|
|T4|写前绝对相位超过模式对应窗口。|MAIN Buck方向27904ticks，Boost26880ticks；历史旧Buck曾用26880。|
|T5|退出相对耗时>936个CPU周期，或MAIN模式对应退出相位超限。|MAIN Buck相位线29952ticks；某些路径耗时未超也可因相位过晚触发。|
|T6|退出检查时发现下一次定时器重复事件REP已经挂起。|处理延续到了下一PWM事件；需要看入口、执行和抢占，不能只归因于某一模块。|
|T7|后台请求在下一请求到来时仍未完成/发布。|MAIN正向Boost窗口40μs（25kHz），其他模式20μs（50kHz）。包括等待与抢占，不等于纯PI时间。|

T1～T6主要约束每个快速PWM中断；T7约束多速率后台请求。把Boost计算降到25kHz，不等于把ADC或快速保护也降到25kHz。

## 六、你遇到过的Keil/Watch提示

这些属于调试工具问题，不是OLED上的功率保护码。

|提示|含义与已有结论|
|---|---|
|Cannot access Memory|调试器无法可靠读取目标内存。曾有同一fault独立项与结构体矛盾、多个浮点同为异常小数，不能拿残留读数分析电气原因。|
|Cannot access target. Shutting down debug session.|目标连接或访问失败。历史有断电后出现，也有请求暂停时出现；不能统一归因于一个硬件原因，更不能认为CPU已成功暂停。|
|Internal command error|曾与上述访问失败同时出现，是调试命令失败提示；不是新的控制器故障编号。|
|power_diag.fault cannot evaluate / undefined identifier|当前统一诊断可被编译关闭，没有该对象时不能求值属预期；不证明ADC没工作。|
|静态sample_valid或旧Watch表达式cannot evaluate|符号作用域、表达式、优化或AXF不匹配等可能导致无法求值。优先看当前配套AXF的公开power_status，不把它当作ADC故障1。|

## 七、如何对应“原因”而不误判

- fault是位掩码，不是顺序编号。0x40=64，0x10=16；后续故障可能OR入，要优先看首故障。复合数值不能直接套单码名称。
- 优先保存power_status的fault/detail、fault_v_left/right、fault_il、fault_input_volts与fault_raw_*；时序再看fault_elapsed_cycles/fault_spacing_cycles/fault_counter_ticks。
- 看power_event.fault.valid/code/detail/state及ADC专用adc_reason、入口标志；停止后仍更新的实时v_left/v_right不是当时首故障值。
- **S7等请求拒绝时，power_event中的mode/target可能属于上一次配置**：active_mode/active_target在校验通过之后才更新。要结合实际菜单或Power_RequestStart入参确认本次请求。
- 当前固定4.8μs输入采样没有动态避沿；“同样采样频率”也不等于电流/两路电压都在同一个时刻采到。
- 12V、100Ω升36V所需理想输入1.08A已超过0.7/0.9A电源限流；这是已确定的功率预算不足。它不能直接解释S7，CC限流导致瞬降是否就是本次欠压的唯一原因仍需波形证实。
