# Buck 优化版：输入晚采样与7V保护实验

工程：`MDK-ARM/bench12_buck_fast.uvprojx`

Target：`bench12_buck_fast`

固件：`MDK-ARM/bench12_buck_fast/bidreaction_bench12_buck_fast.hex`

首页：`12V BUCK ADC2 OVP7`；参数页：`SW-A2-7`。继续使用同一活动工程，
旧工程只是历史参考，共享当前源码。

## 本次变化

- 2026-10-28：只改变输入电压的采样路径。ADC1原电流、左电压、右电压三路
  注入采样及TRG2/CMP2保持；ADC2规则组在Timer A CMP4=23040，即周期4.8µs，
  由HRTIM TRG1采同一PA0。输入控制、启动判断和输入故障快照使用ADC2。
- ADC2每周期必须同时有EOC/EOS且无OVR；缺失、不完整或溢出不退回ADC1早样本。
  活动阶段立即报ADC故障，停止阶段取消样本有效资格。初始化失败不启动PWM计数器。
- 用户随后报告故障4并明确要求提高至7V。当前FAST保护比率由1.1改为7/6，
  6V目标对应7.0V；低目标仍按比例（3V对应3.5V），其他构建仍为1.1倍。
  超出门限仍单次采样关断。PI、目标上限6V、10–14V输入窗口及840/936周期保护保持。
- 按用户要求，启动请求、初始预充电和等待使能阶段统一使用
  `|采样电流| < 0.5A`、`右输出电压 <= 1V`。电流恰好 ±0.5A 仍拒绝。
- 仅在本工程裁掉不参与 Buck 控制的 Boost 预充电、延时及额外斜坡计算。
  有效 Buck 滤波、软启动、PI、积分更新次序和抗饱和保持原算法。
- 非 Buck 模式在后端拒绝；若直接误调控制器，也会锁存错误并清零控制输出。
- 仍为 12V 受限台架：输入 10.0–14.0V，目标 1–6V，电流参考上限0.5A，
  采样过流1.5A。OCP 未确认；没有把硬件保护标成已验证。
- OLED 活动期间仍暂停刷新，并未改为 DMA。所有时序保护保持原值。

2026-10-26追加：用户报告实际输入在万用表及示波器上约11.9–12V，而故障
采样先后为13.53V及10.31V，并要求适当增加报错范围。仅在当前FAST工程把输入窗口
由10.5–13.5V改为10–14V，启动请求和运行期间共用门限。越界仍单次采样关断，不增加滤波
延迟。这不是采样链路修复；后续若仍出现较大采样偏差，应检查ADC分压点及地参考。

提高启动电压门限只是允许更多残余电压，不代表此前0.346V/0.589V采样
已证实为噪声。允许带电输出冷启动可能增加反向电流，实际需台架观察。
HOLD 恢复条件不属于冷启动，仍沿用原来的0.25A，当前受限 Buck 不进入该反向路径。

## 为什么写入期限是840周期

150MHz CPU、150kHz PWM，每周期1000个CPU时钟。
代码在写PWM之前要求本次中断耗时不超过1000−160=840周期（T3），
并要求定时器不超过32000−5120=26880刻度（T4）。5120刻度相当于160个CPU时钟。
前者监控计算耗时，后者监控真实周期位置；中断入口有延迟，所以两者都需要。
写入后还有936周期收尾检查（T5）及下一周期到达检查（T6）。

160是软件预留裕量，不是芯片指定的常数。若要缩小，需要测量最坏写入/
收尾耗时和入口抖动，不能只为消除报错而改。当前截图931周期、计数31744，
距32000仅256刻度，约8个CPU时钟或53ns；即便单独把T3改为950，仍违反T4。

左右PWM比较值先写入预装载寄存器，再在周期边界生效。成对写入期间禁止
两桥更新。错过边界可能使旧占空比多保持一周期，增加控制延迟，跨边界写入
也会破坏预期更新时序。是否造成危险取决于电流、电感、占空比及负载，
不能把“未立即损坏”当作时序正确。

## 验证与下一次操作

本地主机测试25组通过，包括54万个采样点的普通/优化Buck分支逐位输出及
有效状态对比、正负启动电流/电压边界、故障停机、理想开关模型，以及ADC2配置失败、
早/晚输入分歧和各活动阶段坏样本保护。7V版还验证6.6875V可通过，
7V两侧相邻ADC码的通过/关断和首次故障快照，以及3V目标的比例保护。
理想模型仍保留更严格的6.6V启动峰值回归断言，不因提高保护线而放宽模型要求。
这些不能替代板上时序和电气验证。ARM编译0错误0警告；CCM向量、启动拷贝、
代码位置和无插桩检查通过，CCM代码3384字节。forward_step仍为696字节，
字节数不等于周期数。37.5MHz ADC时钟下，计算的ADC2最晚完成时刻约5.853µs，
距周期末约0.813µs；需实测确认。固定4.8µs也不保证所有占空比下都远离开关沿。

1. 在功率输出已停止且旧现场已保存后下载本工程固件，核对首页身份。
   保持此前12V电源、0.2A电源限流、右侧100Ω负载和6V目标。
2. 先不发启动命令，比较ADC1 JDR2与ADC2 DR/`power_status.raw_vh`的直流读数及
   万用表输入电压。两颗ADC的偏置/增益可能不同，不能把偏置变化误判为相位去噪。
   调试暂停会使标志溢出，只在停止状态暂停，随后恢复并等待连续新样本再启动。
3. 正常连续运行后手动启动，用相同示波器设置对照输入/PA0波形与故障输入值。
   活动期间不要单步或暂停CPU；OLED暂停刷新本身不是死机。
4. 若报错，输出关断后再暂停读取：`fault`、`fault_detail`、`fault_elapsed_cycles`、
   `fault_counter_ticks`、`fault_raw_vh`、`fault_input_volts`、`v_reference`、
   `fault_v_right`、`fault_il`。新构建后地址可能变化，使用匹配AXF的符号和map。
5. 若正常运行，先按K4停止，再读取`isr_cycles_max`，记录实际输出峰值、稳态值与
   是否仍报输入保护。旧版755周期不可当作本版实测值。

当前7V版本尚未下载或启动硬件。输入噪声是否改善、ADC2直流一致性及新增IRQ开销均待实测。
提高保护线只增加允许的过冲，不改变PI；需用示波器记录启动峰值、稳态值及故障采样，
不能把不再报故障4直接当作超调已经修复。
