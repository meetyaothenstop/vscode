## 3. 当前控制结构与保护：不要沿用旧文门限

代码采用 **150kHz定时中断实时控制＋前台循环服务**，未在本轮引入RTOS任务调度。main循环调用Power_Service、PowerUI_Service及HAL_Delay(1)；OLED前台约200ms调度DMA刷新，启动阶段静默，STOP/按键优先。时序问题需核对具体IRQ分支和PWM共同更新边界，增加RTOS本身不扩大周期预算。RES1做的是中断内恢复步骤分期。

| 项目 | MAIN正向Buck / 反向Buck | MAIN正/反Boost |
| --- | --- | --- |
| 输入方向 | 正向左输入右输出；反向右输入左输出 | 按方向对应 |
| 菜单范围 | 输入12–40V、输出0–36V，1V步进；非零后端1–36V | 原升压关系 |
| 默认菜单 | 正向24→12V；反向已改为12→6V | 由设置选择 |

| 输出过压线 | **min(max(最终目标×1.5,6V),40V)** | 原最终目标×1.1 |

## 6. RES1具体实现及不变的时序保护

反向运行输出≥最终目标×1.005时进入HOLD全关断；原恢复条件为输出<目标×0.99且|IL|<0.25A。
RES1仅MAIN mode3变化：

1. HOLD满足恢复条件时，原控制器准备、计算、映射并缓存比较值；保持四路全部关断，置私有resume_bootstrap_pending，state=POWER_BOOTSTRAP、bootstrap_resume=1、bootstrap_cycles=31（表示待开通准备间隔）。
2. 下一IRQ先用新鲜样本执行原ADC、输入、输出、电流等保护，再复查恢复条件；通过才begin_bootstrap(1)，开低侧并设置30周期；不通过回HOLD、保持全关断。
3. 低侧完整30周期后写入缓存plan，再等2周期让比较值跨共同装载边界，随后开全部输出。新增早期开通/取消分支都走共同T5/T6，不重复控制器计算。

多一个全关断周期约6.667µs，缓存plan比旧流程多等一周期。STOP、零目标、清故障、故障及新请求取消pending；无新公开状态/命令。正向和Boost/台架逻辑保持，PI、PWM频率/死区、ADC与电气保护保持。

| 子码 | 当前含义 |
| --- | --- |
| T1 | 相邻IRQ入口间隔>1256CPU周期 |
| T2 | 入口计数>8192ticks |
| T3 | 写前相对耗时>840CPU周期 |
| T4 | MAIN正/反Buck写前相位>27904ticks；Boost/台架仍26880 |
| T5 | 收尾相对耗时>936CPU周期，或MAIN正/反Buck退出相位>29952ticks |

每周期1000CPU时钟/32000高分辨计数。W128预留128CPU周期、退出预留64周期是工程设置，不是实板WCET证明；T5事后检测不能倒退已经发生的更新。普通硬件成对写入同口径13条ARM指令，仍成对阻止预装载转移/写两个比较值/恢复转移。不要把加入两个状态写与分支后的16条误报为硬件写入回归。

## 7. Watch读取：新旧绝对地址必须区分

`state=0x04 POWER_FAULT`仅表示状态枚举；真正故障号看fault。fault=4是输出过压；fault=64/detail4是T4，fault=64/detail5才是T5。无插桩版没有power_diag.fault，不能求值不是ADC故障。
故障后raw/v_left/v_right/il等遥测继续更新，应优先读fault_*首故障锁存；isr_cycles_max只到写后检查点，不含整个异常返回，也不能直接与写前840比较。

| 对象 | 旧W128地址（只用于旧版） | 当前RES1地址/宽度 |
| --- | --- | --- |
| power_status | 0x20000B10 | 0x20000B14 |
| bootstrap_resume | 0x200001B0 / 1字节 | 0x200001B4 / 1字节 |
| bootstrap_cycles | 0x200001FC / 4字节 | 0x20000200 / 4字节 |
| resume_bootstrap_pending | 无 | 0x200001AC / 1字节 |

地址只对相应指纹和MAP有效。当前RES1静态名无法求值时，可在Watch空白Name行分别只读：


这不是让用户修改Value。下载RES1后必须加载配套AXF，不能沿用上一轮W128的两个地址。此前通过旧地址读到1/30是旧W128现场，不是RES1试验结果。
